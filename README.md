# Re-Hardwire

Re-Hardwire is a mobile-first self-help app with a guided practice library that can run on the device without a network connection. Optional coach chat and cross-device sync use a separately configured backend.

The app is for education and self-guided support. It does not diagnose, provide emergency monitoring, or replace care from a qualified professional. The guided practices link to their public source material; Re-Hardwire's adaptations have not yet received an independent clinical review.

## Current architecture

- `frontend/`: Next.js and React web app, with a service worker for offline browser use and Capacitor configuration for packaged Android/iOS builds.
- `backend/`: FastAPI prototype for optional routing, chat, text-to-speech, profile, and history APIs.
- `docs/CLINICAL_CONTENT.md`: source and review policy for the self-help library.
- `docs/SECURITY_AND_PRIVACY.md`: local data behavior, secret handling, and deployment boundaries.
- `docs/API.md`: API discovery and versioned capabilities contract.
- `docs/OFFLINE_AND_DEPLOYMENT.md`: offline and packaging notes.

Next.js/Capacitor is the current frontend. The former Streamlit implementation is historical and is not the supported launch path.

## Start the frontend

Requirements: Node.js 20 or newer and Python 3.11 or newer.

Run these commands from the repository root. Install dependencies once, then start the frontend and local API together:

```powershell
npm --prefix frontend ci
npm run setup:backend
npm run dev
```

`npm run setup:backend` creates and prepares `backend/venv`; repeat it after changing Python dependencies. It skips installation when the existing environment already imports successfully. The backend listens only on `127.0.0.1:8000`; the frontend is at [http://localhost:3000](http://localhost:3000). Press Ctrl+C in the same terminal to stop both services.

The backend defaults to a local scripted coach and needs no provider key. Guided tools and local chat remain available offline. External LLM providers require separate backend configuration in `backend/.env`.

## Start the backend separately (optional)

Requirements: Python 3.11 recommended. The backend includes machine-learning dependencies and can take time and disk space to install.

```powershell
cd backend
python -m venv .venv
# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# macOS/Linux:
# source .venv/bin/activate
python -m pip install -r requirements.txt
Copy-Item .env.example .env   # Windows PowerShell
# cp .env.example .env        # macOS/Linux
uvicorn app.main:app --reload
```

Set `NEXT_PUBLIC_API_BASE_URL` when building the frontend if the API is hosted somewhere other than `http://localhost:8000`. This is a public URL setting; never put a provider key in a `NEXT_PUBLIC_*` variable or frontend source.

The backend currently stores profile/history data in shared JSON files and does not provide production user authentication or per-user data isolation. Keep it on a trusted development machine. Do not expose it to the public internet or use it for real users until authentication, authorization, per-user storage, secure deployment configuration, and privacy controls are implemented and reviewed.

## Offline behavior

- Guided practices and the personal support plan are stored with the app and run locally.
- The browser app needs to be loaded once while online before the service worker can cache it. A Capacitor app bundles the static frontend, so its first app launch does not need to fetch the frontend from a website.
- Local profile, preferences, wins, and session data stay in the browser/device unless a user-configured backend sync is used.
- Coach responses are not generated by an on-device language model. Offline chat offers a clearly labeled local check-in and links to the guided tools.
- Calling/texting a crisis service or syncing data still requires the relevant phone or network connection.
- Use **Prepare for offline** on Home to cache and verify the core app pages. It reports missing items instead of claiming the app is ready when the cache is incomplete.
- Clinical conversation review sharing is disabled. Online coach messages still go to the configured reply service to generate a response; that is separate from clinical review.

## Build and package

From `frontend/`:

```sh
npm ci
npm run build
npm run build:capacitor
npx cap sync
```

Add Android or iOS once with `npx cap add android` or `npx cap add ios`. Native builds require the platform's standard development tools. See [offline and deployment notes](docs/OFFLINE_AND_DEPLOYMENT.md).

## Checks

GitHub Actions runs frontend lint, type-check, and production build checks, plus the existing backend test suite, on pushes and pull requests. Run those checks locally with:

```sh
cd frontend && npm run lint && npm run typecheck && npm run build
cd ../backend && python -m pytest -q tests
```

## Safety and content

The guided library is source-linked self-help, not a treatment plan. Clinical review is pending. See [the clinical content policy](docs/CLINICAL_CONTENT.md). U.S. 988 resources are available in the app, but the app cannot assess risk, monitor someone, or contact emergency services for them.
